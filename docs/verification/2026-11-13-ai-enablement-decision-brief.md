## 1. 結論サマリ

- 技術ゲートは **G1/G2/G3/G4/G5 が PASS**（G3 は費用算出済み・Console 照合待ち）、G6 は既存 CI で PASS。
- 実キー canary は **合計 6 リクエスト**と小規模。品質は 2 名評定（2 名目は AI 再評定）で全次元「十分」だが、
  **サンプルの少なさ・モデル更新・注入パターンの限界**は残る。
- 推奨は **B: 限定パイロット**（本番へ配備するが既定 OFF を維持し、1〜2 プロジェクトで assist を使う）。
  既定 ON（C）は、もう一段の実利用データと費用の Console 照合を待つ。

## 3. 費用

- 公式単価（2026-11-13 取得）: Opus 5.5 input **$4/MTok**、output **$20/MTok**。
- 04/05 canary（3 req）: input 1,666 / output 4,741 → **$0.10148**（平均 **$0.0338/req**）。
- 03 討論（代表 1 req）: input 517 / output 1,699 → **$0.03605**（元の 3 req は未計測、代表値で代替）。
- 合計（measured 4 req）: **$0.13753**。
- 目安: 03 は 100 req で約 **$3.60**、04/05 は 100 req で約 **$3.38**（同一傾向が続く場合の単純計算）。
- 実額は Anthropic Console の Usage / Cost で照合する（税・クレジットは Console が正）。

## 4. 品質・安全性の要点

- 討論は「定量部分は根拠不足」と正しく留保し、捏造引用を入口で排除。注入は「資料の内容としてのみ扱う」と拒否。
- 批判・候補は 04/05 の型（type/vars/cat/text）を守り、**採点値（scores/total/status）を返さない**。
- 監査に本文・プロンプト・鍵を残さない。採用時のみ保存し、provenance を付ける。
- 既存の決定論（検証・スコア・採択）は変更していない。

## 5. 残リスク

| リスク | 内容 | 現状の統制 | 既定 ON 前に必要なこと |
|---|---|---|---|
| サンプル不足 | 実キーは 6 リクエスト・1 モデル | 固定シナリオで再現確認 | 実利用 1〜2 週間のログ・品質確認 |
| モデル更新 | ベンダー側の挙動変化 | promptVersion と canary 記録 | 更新時の再 canary（同手順） |
| 注入の網羅性 | 1 パターンのみ | プロンプトで DATA を隔離 | 追加パターン（多言語・長文・分割） |
| 評定の独立性 | 2 名目は AI 再評定 | 1 名目と一致を確認 | 人間 2 名目を望むなら追加 |
| 費用の不確実性 | 03 は代表 1 req の計測、Console 未照合 | tokens 記録を実装・代表値を計測 | Console 照合・日次上限の検討 |
| データ越境 | Anthropic への送信 | 研究文書の限定フィールドのみ | データ分類・契約の確認（Q5） |
| 運用負荷 | 監査・利用状況の見守り | 監査イベント | ダッシュボード/アラートは未実装 |

## 7. 推奨（B）の条件

1. 03 討論の tokens を 1 回計測し、費用の目安を確定する。**（完了: $0.03605）**
2. Anthropic Console で 04/05 の実額を照合する。
