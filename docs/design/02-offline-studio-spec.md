## 1. 全体像

「研究着想・仮説洗練プラットフォーム」として、研究者が **6 ステップ**で仮説を洗練する。
ルールベースの「AI エージェント」が 10 タスクを DAG 実行し、討論・根拠評価・新仮説比較・報告書生成までを支援する。

```
トップバー（ブランド / 全体進捗 / 研究テーマ選択 / 新規 / JSON 保存・読込 / 保存状態）
警告ノート（模擬データ・AI ではない旨）
左ナビ 01〜06（各ステップの状態表示） │ main（選択中ビュー）
トースト（右下・3.6 秒）
```

## 3. 画面仕様

各画面は `pageHead(番号, タイトル, 説明, 右側アクション)` で始まり、必要に応じて `staleBanner()`（仮説変更後に再実行を促す警告）を表示する。

### 3.1 01 研究仮説登録

- 右アクション: `改訂として記録` / `研究フローを開始 →`（primary）。
- 左カラム:
  - 研究テーマ: 研究テーマ名（maxlength 80）、研究分野（自動判定＋河川・水工/地盤・土質/コンクリート・材料/施工・生産性/その他）、研究仮説（5 行・プレースホルダ例）、背景・目的（3 行）、前提条件・適用範囲（3 行）。
  - 研究条件・制約: 予算（潤沢/標準/厳しい）、期間（余裕あり/標準/短期）、安全性・倫理重視チェック、説明ヒント。
  - 研究データの管理: localStorage の説明、`この研究をJSON保存`、`この研究を削除`（confirm）。
- 右カラム:
  - 仮説構造チェック（`ライブ` チップ）: 入力中にリアルタイム更新（§4.1）。
  - 架空の研究事例を追加: 4 サンプル（分野チップ・タイトル）。
  - 改訂履歴: `r{n}`・メモ・日時・仮説抜粋・`復元`（confirm）。

### 3.2 02 AIタスク管理

- 前提: 仮説が空なら空状態（`◇`・メッセージ・01 へのボタン）。
- コントロール: `▶ 実行開始` / `⏸ 一時停止`（状態で切替）、`⏭ ステップ実行`、`↻ 全体を再実行`（confirm）、速度 ×0.5/1/2/4。
- 承認待ちバナー: タスク名・承認情報・`承認する` / `差し戻して再実行` / `内容を確認`。
- 統計 5 項目: 全体進捗 % / 完了 n/10 / 実行中 / 承認待ち / 状態（実行中・完了・停止中）。
- タスク依存関係: SVG DAG（列＝依存レベル、ノードに担当エージェントの色付き丸・短縮名・状態・◆承認・進捗バー、完了エッジは強調）。
- タスク一覧: # / タスク（説明付） / 担当エージェント（アバター＋名前） / 依存 / 状態バッジ / 進捗バー＋% / 実行回数 / 操作（承認・差戻し・再実行）。
- 実行ログ: 最大 120 件、`時刻  メッセージ`、空時メッセージ。
- 10 タスク（key / 依存 / 承認 / 目安秒）:
  1. struct 仮説の構造化（–）
  2. lit 文献・資料調査（struct）
  3. method 変数定義・測定計画（struct）
  4. verify 根拠の信頼性検証（lit, **承認**）
  5. ethics 研究倫理・安全性確認（method）
  6. critic 批判・反証レビュー（verify, method）
  7. debate 複数AI研究討論（critic, ethics）
  8. ideate 新仮説の創出（debate）
  9. evaluate 統合評価・仮説比較（ideate, **承認**）
  10. report 研究報告書ドラフト作成（evaluate）
- 実行モデル: 依存が完了したタスクを `ready` にし、**最大 3 並列**で進捗を進める（260ms 間隔、速度倍率）。承認タスクは完了時に `approval` で停止し、承認で `done`。差し戻しは `ready` に戻し再実行。全完了時は完了トースト。
- 「フロー開始」は 02 へ遷移して実行開始。「即時実行」（`runUpTo`）は対象タスクまで一括完了（確認・承認は自動で行わない）。

### 3.3 03 複数AI討論

- 前提: 討論未生成なら空状態（`◎`・前工程の説明・`debate` 即時実行ボタン）。
- 右アクション: `▶ 討論を再生（残りN）` / `⏸ 再生を停止` / `⏭ すべて表示` / `↻ 討論を再生成`。
- 左カラム: 参加エージェント 8 体（名前・役割・立場チップ）、合意度メーター（0–100、`対立`〜`合意`、例示指標の注記）。
- 右カラム: 討論タイムライン（ラウンド見出し、発言者アバター・名前・種別チップ・本文、`新しい発言` アニメーション、タイピング表示）、件数 `shown/total`。
- 入力: クイックチップ 6 種（反論する・条件を変更・予算制約・期間制約・安全・倫理・データ不足）、テキストエリア（Ctrl/Cmd+Enter 送信）、`発言する`。
- 討論は 5 ラウンド構成（論点共有・批判と検証方法・発散・収束・研究者との対話）。研究者の発言はルールに基づき応答し、計画・評価へ反映。

### 3.4 04 根拠・反証

- 右アクション: `資料を取込（.txt/.csv/.json）` / `＋ 手動で追加`。
- 手動追加フォーム: タイトル / 種別 / 発表年 / 標本数 / 立場 / 概要 / `追加する` / `閉じる`。
- 統計 5 項目: 資料数 / 支持 / 反証 / 平均信頼性 / 未対応の指摘。
- 左: 根拠資料リスト（関連度順）。各資料に、タイトル、`架空・模擬データ` または `取込資料`、種別・年・n・立場・信頼性チップ（75+ good / 55+ warn / それ未満 bad）、概要、注記、信頼性・関連度のミニバー、タグ、立場セレクト、`根拠に含める/除外`、取込資料のみ削除。
- 右:
  - 批判・反証レビュー: 重要度チップ（高/中/低）・観点・状態・対応/却下/未対応に戻す・指摘本文・改善案。
  - 棄却条件: 番号付きリスト＋説明。
  - 検証計画: 主/補/代替の手法（費用・期間・妥当性 1–5）、測定項目表（独立変数/従属変数/関連変数/統制変数）、研究デザイン。
  - 研究倫理・安全チェック: 区分（要確認/問題なし）・項目・対応方針。

### 3.5 05 新仮説比較

- 右アクション: `↻ 新しい仮説を再生成`。
- 前提: 候補なしなら空状態（`◈`・`evaluate` 即時実行）。
- 最高評価バナー（例示指標である旨）。
- 候補カード: ラベル・類型・状態チップ（採択/却下/保留/候補/主仮説）・研究者修正チップ・総合点・本文（または編集中テキストエリア）・提案元・変数・5 指標バー（実験負担は反転表示）・操作（採択/保留/却下/修正/保存して再評価/取消/主仮説にして再実行）。
- 重み付け: 5 スライダー（0–50）＋現在値、変更で総合点・順位・チャート即時更新。
- レーダーチャート: 5 軸、選択候補（チェックボックス）、凡例。
- 総合点ランキング: 横バー＋表（根拠/検証/負担/重要/新規/総合）、指標算出の説明。

### 3.6 06 研究報告書

- 右アクション: `HTMLで保存` / `テキストで保存` / `JSONで保存` / `印刷 / PDF`。
- 未完了時バナー（全工程を即時実行）。
- 研究者所見: テキストエリア（報告書の第 10 章へ反映）。
- 報告書（`.report`: 白背景・明朝・最大 900px・11 章）:
  1. 研究概要（背景・目的／前提条件／研究条件）
  2. 主仮説と構造（引用・IV/DV・方向・数値基準・メカニズム・条件・対照・構造スコア）
  3. 作業の実行状況（10 タスクの担当・状態・完了日時）
  4. 根拠の整理（件数・平均信頼性・資料表）
  5. 批判・反証レビュー（重要度・観点・指摘・状態・改善案）＋棄却条件
  6. 検証計画（デザイン・手法・測定項目表）
  7. 研究倫理・安全
  8. 複数AI討論の記録
  9. 新仮説の比較（重み・全候補の指標・判断）
  10. 研究者の判断記録と所見
  11. 次のステップ（提案）
- 冒頭の警告文とフッター（offline rule-based simulation）を必ず含む。

## 4. ルールベース・エンジン（期待値の基準）

### 4.1 仮説構造チェック（ライブ）

- 分野判定: 分野キーワード（各 +2）＋変数一致数でスコア最大の分野。既定 `general`。
- 変数抽出: 分野辞書の変数名・別名を仮説文中から検出（初出順）。
- 独立変数（IV）/従属変数（DV）: 客観指標（`o` フラグ）の最初の変数を DV、その直前の変数を IV と推定（なければ DV 以外の最初）。
- 構造スコア（/5）: ①変数が 2 つ以上 ②数値基準あり（単位付き数値）③変化の方向あり ④因果メカニズムの記述 ⑤条件・比較の記述。
- 表示: 変数チップ、IV/DV、方向、数値、メカニズム・条件・比較の有無、スコア、改善ヒント。

### 4.2 信頼性・関連度

- 信頼性: 種別重み（TYPE_W）＋発表年（2020 以降 +5、2012 未満 −10）＋標本数（100 以上 +5、5 未満 −14、20 未満 −5）、10–98 にクランプ。
- 関連度: 仮説変数とタグの一致率×78＋IV 一致 +12＋DV 一致 +10（0–100）。取込資料でタグ無しは 20、内蔵資料は 0。
- 平均信頼性: 信頼性が付いた資料の平均（四捨五入）。

### 4.3 合意度（例示）

`50 + 高信頼支持×6 − 未対応(高)×9 − 未対応(中)×3 + 対応済み×3 + 採択候補あり×8`、3–97 にクランプ。

### 4.4 新仮説の評価

- 5 指標（各 5–95）: 根拠の充足度 / 検証可能性 / 実験負担（低いほど高評価） / 研究上の重要性 / 新規性（例示）。
- 総合点: 重み（既定 25/25/15/25/10）で加重平均（`totalOf`）。
- 浮動小数の揺らぎは仮説本文のハッシュで固定（同一入力で再現的）。

### 4.5 タスク実行

- 依存充足で `ready`、最大 3 並列、`running` の進捗増加、完了で `done`（承認タスクは `approval`）。
- 承認/差戻し/再実行/全体再実行の状態遷移は §3.2 のとおり。
- タスク完了時の効果（EFFECTS）: 計画生成・倫理チェック・批判生成・討論生成・候補生成・報告書確定。

## 5. 実装へのマッピング（本リポジトリ）

| プロトタイプ | 実装 |
|---|---|
| トップバー＋警告ノート＋左ナビ＋6 ビュー | React（`apps/web`）で移植。CSS はプロトタイプの定義をそのまま採用（スコープ付き） |
| ローカル状態 `DB` / `P` | 研究ごとの文書をサーバー保存（新テーブル `research_documents`: `project_id` PK / `version` / `payload` JSONB / `updated_at` / `updated_by`）。楽観ロック（expected_version、409） |
| localStorage 自動保存 | 変更を 500ms デバウンスで `PUT /api/projects/{id}/research`。保存状態表示は「サーバーに自動保存済み」 |
| JSON 保存/読込 | 全研究エクスポート/インポート API（またはクライアント生成 JSON）＋サーバー保存 |
| 認証 | 既存のセッション＋CSRF＋Cloudflare Access 自動ログインを維持（プロトタイプ外の必須要素） |
| 監査・利用者管理・設定 | トップバー右の「管理」メニューへ退避（プロトタイプの画面構成を崩さない範囲） |
| 既存 API（sources/claims/reports/verification） | 変更せず保持（新 UI からは未使用。将来の連携余地） |

### 5.1 逸脱（明示）

1. **認証**: ログイン/Access 自動ログインは残す（プロトタイプに無い）。未認証では研究データ API を拒否。
2. **保存先**: localStorage → サーバー（監査・複数端末・バックアップのため）。保存状態の文言のみ調整。
3. **管理機能**: 監査ログ・利用者管理・設定は「管理」メニューに退避（削除しない）。
4. **オフライン警告**: プロトタイプの文言を維持しつつ、実装がサーバー保存であることは Runbook に記載（画面文言は変えない）。

## 5.2 実装上の追記（2026-11-03）

- スタイルはプロトタイプ CSS を `.studio-root` 配下にスコープし、**Shadow DOM** に隔離してアプリ本体の
  グローバル CSS（`.brand` の padding 等）と干渉させない。
- 保存は 500ms デバウンス。`version` は送信時点で読み、連続保存でも 409 を出さない。
- プロジェクト名の変更は `PATCH /api/projects/{id}` でサーバー側の一覧にも同期する。
- 左ナビ下部に「管理」「ログアウト」を置く（トップバーの 1 行レイアウトを崩さないため）。
- ナビフッターの「すべてローカル処理（通信なし）」は、サーバー保存へ変更したため「すべてルールベース処理」に変更（文言の逸脱）。
- 保存は 500ms デバウンスだが、テーマ切替・ログアウト・タブ非表示時は `flush()` で即時保存する。
- 保存データはクライアントで型・列挙を検証し、サーバー側でも形状を検証（422）。

- ルールベースの判定（§4）がプロトタイプと同一の入力で同一の出力になる（許容差なし。乱数は本文ハッシュ固定）。
- タスク実行・承認・討論・比較・報告書の状態遷移が §3 のとおり。
- ダークモード・900px レスポンシブ・印刷 CSS・トーストが機能する。
- 保存はサーバーに永続化され、再読込・別端末で復元される。409 競合を検出する。
- 詳細テスト項目（[02-detailed-test-spec.md](../testing/02-detailed-test-spec.md)）を全て実行し、結果を記録する。
