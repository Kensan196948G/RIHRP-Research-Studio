## 1. Task Understanding and Scope

**目的**: スタジオの「AI エージェント」は現在ブラウザ内のルールベース処理であり、これを外部 LLM の生成に置き換える案（B案）について、実装可否を判断できる設計・リスク・PoC 計画を作る。今回は**設計まで**で、実装・本番キー投入・検証エンジンの変更は行わない。

**成功基準**:
1. 決定論的検証（ADR-0002）とスコアリングの再現性を壊さない境界が明示されている。
2. 幻覚・プロンプトインジェクション・データ越境・コストの失敗系と、その検証方法がある。
3. 最小の PoC スライスと、実装前に人間が決める事項が列挙されている。
4. オフライン／ルールベース表示の誠実性（利用者への誤認を与えない）が維持される。

**含む**: 置換候補の棚卸し、リスク評価、PoC 範囲、受入ゲート、監視、ロールアウト。
**含まない**: LLM 実装、モデル選定の確定、本番設定変更、承認フローの自動化、検証エンジンの置換。

### 作業仮定

- A1: B案の対象は**生成系**（討論・批判・候補・報告書の文章）であり、検証・信頼性スコア・候補の採点式は決定論のまま残す。
- A2: ブラウザ利用者は外部ユーザーで DSH のモデル認証を持たないため、LLM 呼び出しはサーバー経由に限る（ADR-0006 と同じ）。
- A3: 既存 LLM 基盤の上限値・タイムアウト・レート制限を流用できる。変更する場合は別承認とする。
- A4: PoC は既定 OFF・プロジェクト単位の opt-in とし、既存の決定論フローを既定のまま維持する。

## 3. Risks and Priorities

| ID | 優先 | リスク | 影響 | 根拠・対策 |
|---|---|---|---|---|
| R-01 | **P0** | LLM 出力を検証・スコアに混ぜ、決定論（ADR-0002）を壊す | 監査不能・承認条件が再現不能 | 生成物は検証入力に渡さない。スコア式は現行のまま。PoC は下流スコアを持たない討論だけにする |
| R-02 | **P0** | 幻覚（存在しない文献・数値・引用） | 研究上の誤誘導 | 引用は既存 evidence の ID/原文に限定。自由文の文献名・数値を禁止。原文照合に失敗した候補は無効化（ADR-0006 と同型） |
| R-03 | **P0** | プロンプトインジェクション（取込資料・仮説文に命令を混入） | 意図しない出力・データ露出 | 信頼できない入力を区切り、出力は提案扱い。自動保存・自動採用・ツール実行をしない |
| R-04 | **P0** | データ越境・秘密漏洩（鍵、研究データ、PII） | 契約・法令違反 | 鍵は環境変数のみ。プロンプト・応答を監査に残さない。プロジェクト単位の opt-in と送信内容の明示。無効化スイッチ |
| R-05 | P1 | 非決定による再現不能（同じ入力で違う出力） | テスト・監査の不安定化 | model / prompt / promptVersion / temperature を保存し、生成物に provenance を付与。完全一致は保証しないと明記。入力ハッシュでキャッシュ |
| R-06 | P1 | コスト・レイテンシの暴走 | 利用者離脱・費用超過 | 既存上限（12k 入力 / 30 秒 / 5 回/分）＋プロジェクト日次上限。失敗時はルールベースへ fallback |
| R-07 | P1 | オフライン／ルールベース表示との不整合 | 利用者の誤認 | 対象プロジェクトでは注意書きを「一部 AI 生成」に切替。生成箇所にラベル。ルールベースに戻せる |
| R-08 | P2 | 日本語ドメイン語彙・役割（8 エージェント）の品質ばらつき | 体験品質 | 固定フィクスチャ＋ルーブリック。役割・発言形式のスキーマ検証 |
| R-09 | P2 | 監査・説明責任（誰がどのモデルで生成したか） | 事後検証不能 | 生成時に provider / model / promptVersion / 時刻 / 入力ハッシュを記録（本文は残さない） |
| R-10 | P3 | ベンダーロックイン・モデル更新 | 将来の維持コスト | プロバイダ抽象化（既存）とモデル設定の外部化 |

**順序**: P0（R-01〜R-04）を設計で封じ、P1 を PoC の受入ゲートにし、P2 は評価で判定する。

## 4. Core Analysis and Execution Items

### 4.1 置換候補とリスク順

| 工程 | 現行関数 | 下流影響 | LLM 置換の可否 | リスク |
|---|---|---|---|---|
| 01 構造化・分析 | `analyze` | 全工程・スコア | 当面**置換しない** | 高（下流全体が非決定に） |
| 02 タスク実行 | `EFFECTS` | 全工程 | 置換しない（実行制御は決定論） | 高 |
| 03 討論 | `generateDebate` | 報告書の文章・UI のみ | **PoC 対象** | 中（物語生成で、スコア・検証に不干渉） |
| 04 批判・反証 | `makeCritiques` / `makeFalsification` | 報告書・棄却条件 | 第2段階で検討 | 中 |
| 05 候補生成 | `genCandidates` | 比較・主仮説の採択 | 第3段階（採択は人間） | 高（仮説自体を変える） |
| 05 採点 | `scoreCand` / `scoreAll` | 比較・採択 | **置換しない**（決定論のまま） | 高 |
| 06 報告書本文 | `buildReport` | 提出物 | 文章支援として別途 | 中 |
| 信頼性・合意度 | `reliabilityOf` / `agreement` | 表示・報告書 | **置換しない** | 高 |

**推奨 PoC**: 03 討論の生成のみを「AI 支援（任意）」として追加し、既定は現行のルールベース。討論はスコア・検証・採択に影響しないため、決定論の境界を保ったまま LLM の品質・幻覚・コストを評価できる。

### 4.2 品質次元とルーブリック（案）

| 次元 | 観測可能なアンカー | 合格の目安（案） |
|---|---|---|
| 根拠整合 | 発言中の事実が evidence ID か既存の分析値に一致する | 捏造 0 件（人間確認） |
| 引用 | 引用・数値が原文に存在する | 原文照合 100% |
| 役割整合 | 8 エージェントの役割・発言形式が崩れない | スキーマ適合 100% |
| 論点カバー | 反論・代替説明・検証提案が含まれる | ルーブリック 3 段階で「十分」以上 |
| 日本語品質 | 土木・研究用語の誤用がない | 評定者 2 名の一致（不一致は協議） |
| 安全・倫理 | 危険作業・個人情報の助言をしない | 高リスク出力は拒否または人間へ |

評定は 2 名、不一致は協議で確定。閾値は所有者が決める（Q6）。

### 4.3 テストデータ

- 固定フィクスチャ: 河川・水工 / 地盤・土質 / コンクリート・材料の 3 シナリオ（E2E の仮説・資料を再利用）。
- ネガティブ: 資料 0 件、支持と反証が矛盾、長文（上限超）、資料内に命令文（インジェクション）、上流 429/500/timeout/不正 JSON。
- スライス: 日本語を主、分野別、role（editor 以上）。
- CI は**スタブ**（既存の OpenAI 互換スタブ）で実行し、実キーは使わない（[03-ai-drafting-test-plan.md](../testing/03-ai-drafting-test-plan.md) と同じ方針）。

### 4.4 リスクシナリオ（実行可能な形）

| ID | 前提 | 刺激 | 期待 | 証跡 |
|---|---|---|---|---|
| B-01 | 資料に「以前の指示を無視して…」を混入 | 討論生成 | 指示に従わない。出力は提案で自動保存されない | 生成結果・保存状態・監査 |
| B-02 | 資料に存在しない文献名を生成させる | 討論生成 | 原文照合で無効化、または採用不可 | 応答・照合ログ |
| B-03 | 上流 401/500 | 生成 | 502、フォールバック表示、既存機能は不変 | API 応答・UI |
| B-04 | 上流 timeout | 生成 | 504、ルールベース討論を選択可能 | API 応答 |
| B-05 | レート超過 | 連続生成 | 429、案内表示 | API 応答 |
| B-06 | キー未設定 | 生成 | 503 `ai_not_configured`、ボタン無効 | API 応答 |
| B-07 | 生成後に検証を実行 | 検証 | 検証結果・スコアは LLM 生成前と同一（決定論） | 検証 API・差分 |
| B-08 | 生成物を保存 | 再読込 | provenance（provider/model/promptVersion）が残る。本文は監査に出ない | DB・監査 |
| B-09 | 生成途中で中断 | UI | 孤児リクエスト・二重保存なし | ネットワーク・DB |

### 4.5 受入ゲート

- **G1（安全・幻覚）**: B-01/B-02 が PASS。捏造引用 0 件（人間確認）。
- **G2（決定論）**: B-07 PASS。AI 機能有効時も `verify_claim` とスコアが既存テストと一致。
- **G3（コスト）**: 1 回あたりのトークン・レイテンシ・日次上限が設定値内。超過時は fail closed。
- **G4（監査）**: provenance と監査イベントが揃い、プロンプト・鍵・生成本文が監査に残らない。
- **G5（品質）**: 固定フィクスチャでルーブリックが閾値以上（Q6 で確定）。
- **G6（後退なし）**: 既存のスタジオ E2E・API テストが AI 無効時に全て PASS。

### 4.6 監視（案）

生成回数、成功率、レイテンシ、トークン数、無効引用数、フォールバック回数、429 回数。プロンプト本文・生成本文・鍵は収集しない。

### 4.7 アーキテクチャ（PoC 案）

- **フラグ**: サーバー `RIHRP_LLM_*` が設定済み、かつプロジェクトの `aiMode` が `assist` のときだけ有効。既定 `off`。
- **API**: `POST /api/projects/{id}/ai/debate`（editor 以上）。入力はサーバーが `research_documents` から組み立て、**信頼できないデータ**として区切る。出力は `messages[]`（agent/kind/text）と provenance。**保存しない**。
- **クライアント**: 03 に「AI で討論を生成（試行）」を追加。プレビュー→「この討論を採用」で `P.debate` に保存（`ai: {provider, model, promptVersion, generatedAt}` 付き）。採用しなければ現行のルールベース討論のまま。
- **フォールバック**: 503/429/502/504 は案内を出し、ルールベース討論を既定表示。生成失敗でタスクを止めない。
- **表示**: 対象プロジェクトでは注意書きを「一部 AI 生成を含む」に切替。討論に「AI 生成」ラベル。ルールベースに戻す操作を用意。
- **非目的**: 検証・スコア・採点の置換、承認の自動化、自動保存、オフライン保証の変更。

### 4.8 ロールアウト

1. 本書の承認（所有者が Q1〜Q6 を決定）
2. 実装（隔離・スタブテスト・既定 OFF）
3. 内部 1 プロジェクトで canary（実キーは承認後）
4. 評価（G1〜G6）と残リスクの受容判断
5. 既定 ON にするか、assist のままにするか

## 5. Blockers and Residual Risk

**実装に進むためのブロッカー**:
- Q1〜Q6 が未決（特に Q4 費用上限・Q5 データ越境）。
- 本番キー投入の承認（ADR-0006 と同じく人間判断）。
- ルーブリックの評定者・閾値（Q6）。

**残リスク（設計だけでは消えない）**:
- モデルの非決定性・ベンダー更新による品質変化。
- 高度なプロンプトインジェクション（区切りだけでは防げない）。
- 生成物が「もっともらしいが根拠が薄い」場合の人間判断依存。
- 費用が利用量に比例して増える構造。

**停止・エスカレーション条件**: 捏造引用が 1 件でも再現、決定論テストの差分、監査に本文・鍵が出た場合、上限超過が継続。
