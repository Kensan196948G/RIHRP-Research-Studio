# RIHRP Research Studio — 企画（Concept）

- 版: v0.1（提案ドラフト / ユーザー最終承認待ち）
- 日付: 2026-11-02
- 位置づけ: 本リポジトリの正本。実装と食い違う場合は、ADR と実装を確認したうえで本書を更新する。

## 1. 背景と課題

AI を使って調査レポートを作る場面では、次の 3 つが壊れやすい。

1. **出典と主張の紐付けが消える** — どの記述がどの資料のどの箇所に基づくのかが、文章の編集で失われる。
2. **「それらしいが根拠が無い」記述が通る** — 生成文の数字・引用が原資料に実在するかを確認する工程が無い。
3. **承認の意味が曖昧になる** — レビュー時に「どこが未検証か」が見えず、承認が品質保証として機能しない。

RIHRP Research Studio は、この 3 つを **根拠スナップショット（内容アドレス固定）** と **決定論的な検証** と **矛盾ゼロを条件とする承認** で解く。

## 2. 提供価値

- 出典は登録時に本文スナップショットを取り、SHA-256 で固定する。以後の改竄・欠落は検出できる。
- 主張（claim）は出典と引用で結び付ける。検証は「引用がスナップショットに実在するか」「主張の数値が根拠に実在するか」を機械的に判定する。
- レポートは主張 ID を参照して組み立てる。承認時には矛盾（contradicted）ゼロを必須とし、未検証件数を明示する。
- すべての業務操作は監査ログ（append-only）に同一トランザクションで残る。

## 3. 利用者と役割

| 役割 | 説明 | 主な操作 |
|---|---|---|
| viewer | 閲覧のみ | 一覧・詳細・承認済みレポートの閲覧 |
| editor | リサーチャー | テーマ作成、出典登録、主張と根拠の編集、検証実行、レポート編集・提出 |
| reviewer | レビュアー | 提出レポートの承認・差し戻し（コメント必須）、監査ログ閲覧 |
| admin | 管理者 | 利用者管理、全操作、監査ログ、テーマ削除 |

職務分離: 自分の提出したレポートを自分で承認できない（reviewer かつ提出者本人の場合は 403）。

## 4. 主要業務フロー（MVP）

1. editor がテーマ（project）を作成する。
2. 出典を登録する（URL / DOI / テキスト貼付）。本文スナップショットと SHA-256 が保存される。
3. 主張を作成し、出典と引用（verbatim）を結び付ける。
4. 検証を実行する。判定は verified / unverified / contradicted / insufficient の 4 種。
5. レポートを作成し、セクション・段落に主張を参照させる。
6. レポート検証を実行し、要対応（矛盾・未検証）を確認する。
7. 提出（submit）する。提出時点の内容は版として固定される。
8. reviewer が承認または差し戻しを行う。承認は矛盾ゼロが条件。差し戻しはコメント必須。
9. 承認済みレポートを Markdown でエクスポートする。検証マーカーと根拠付録が付く。

## 5. スコープ

### MVP に含む

- 認証（メール + パスワード、セッション Cookie）、RBAC（4 役割）
- テーマ、出典（スナップショット + SHA-256）、主張、根拠紐付け、検証
- レポート（セクション / 段落 / 主張参照）、版固定、検証、提出、承認 / 差し戻し
- 監査ログ、ダッシュボード、Markdown エクスポート
- ローカル PostgreSQL、Alembic、pytest、CI、systemd 配備、Health Check

### MVP に含まない（将来）

- 外部 URL の自動取得クローラ（MVP は貼付本文を正とする。URL は出典識別子として保存）
- PDF / Office ファイルの本文抽出（MVP はテキスト / Markdown 貼付）
- 複数組織（テナント）分離、プロジェクト単位のメンバー管理
- SSO / OIDC（本番は Cloudflare Access を前段に置く）
- リアルタイム共同編集、コメントスレッド、通知

## 6. 成功条件（受入）

- 主要フロー（テーマ作成 → 出典登録 → 主張 + 根拠 → 検証 → レポート → 提出 → 承認 → エクスポート）が UI と API の両方で完走する。
- 改竄されたスナップショットは contradicted になり、承認が 409 で止まる。
- 未検証・不足・矛盾がダッシュボードと承認画面に件数表示される。
- 監査ログに操作・実行者・対象・時刻が残り、更新・削除 API が存在しない。
- ビルド・テスト・CI・Health Check・主要 API 実測の証跡がある。
