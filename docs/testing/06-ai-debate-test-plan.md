# 06. AI 討論（Phase 3 B PoC）テスト計画

- 版: v1.0（2026-11-13）
- 対象: `POST /api/projects/{id}/ai/debate` と 03 討論の「AIで討論を生成（試行）」
- 関連: [ADR-0007](../adr/0007-studio-ai-debate.md) / [Phase 3 B 設計](../design/03-studio-llm-replacement-plan.md) / [AI 機能の変更フロー](04-ai-feature-workflow.md) / [AI 下書きテスト計画](03-ai-drafting-test-plan.md)

## 方針

- CI は**スタブ**（OpenAI 互換のローカル HTTP）で実行し、実キーを使わない。
- 実キーでの確認は人間の承認後のスモーク 1 回だけ（CI 外）。
- 生成物は保存されないこと、採用時だけ `debateAi` 付きで保存されることを確認する。
- 鍵・プロンプト本文・生成本文が応答・監査・ログに出ないことを確認する。

## 1. 入力監査

| 区分 | 内容 |
|---|---|
| known | 対象 API/UI、既存 LLM 基盤（ADR-0006）、既存の研究文書スキーマ、レート制限・タイムアウト |
| missing | 実モデルでの品質・幻覚率、実キーの有無、評価ルーブリックの評定者・閾値 |
| conflicting | なし（assist のため決定論の対象外） |
| stale | モデル名・価格は変動しうる。ADR/設定を正とする |
| out_of_scope | 実キー投入、本番配信、他工程（批判・候補）への拡大、自動品質ゲート |
| assumptions | スタブは debate プロンプトに `EVIDENCE_IDS` を含むため、討論 JSON を返すよう分岐できる |

## 2. リスクと優先度（llm-hallucination-testing 適用）

| ID | 対象/ルール | トリガー | 期待 | 根拠の状態 | 優先 | 担当 | 完了条件 |
|---|---|---|---|---|---|---|---|
| LHT-01 | 引用 ID の実在 | モデルが存在しない ID を返す | その発言を破棄（全滅なら 502） | スタブで実測（D-05/D-06） | P0 | API | テスト PASS |
| LHT-02 | 事実主張の根拠整合 | 実在 ID を引くが内容が支持しない | 自動では検出できない。人間レビューで判定 | **未実行**（実キー必要） | P1 | QA/所有者 | ルーブリックで確認 |
| LHT-03 | 引用なしの事実主張 | `evidenceIds` なしの断定 | 現状は許容。プロンプトで引用を要求するが強制ではない | 設計のみ | P1 | QA | 実キー評価で確認 |
| LHT-04 | 根拠不足時の棄権 | 資料 0 件・不足 | 「根拠不足」を明示し、捏造しない | **未実行**（プロンプトにルール追加済み） | P1 | QA | 実キー評価で確認 |
| LHT-05 | インジェクション | 資料に命令文を混入 | 指示に従わず、提案に留まる | **未実行**（実キー必要） | P0 | セキュリティ | 実キー評価で確認 |
| LHT-06 | 数値・単位 | 原文と異なる数値・単位 | サーバーは検出しない。人間レビューで判定 | 設計のみ | P1 | QA | 実キー評価で確認 |

**注**: evidence ID の実在チェックは「捏造引用の入口」を塞ぐが、**主張の支持関係**までは検証しない。
後者は決定論で判定できないため、人間レビューとルーブリックに残す（[Phase 3 B 設計](../design/03-studio-llm-replacement-plan.md) §4.2）。

## 3. テストケース

### API（スタブ）

| ID | 前提 | 手順 | 期待 |
|---|---|---|---|
| D-01 | 仮説・資料あり | 生成 | 200、`messages[]` と meta。研究文書は不変 |
| D-02 | viewer | 生成 | 403 |
| D-03 | キー未設定 | 生成 | 503 `ai_not_configured` |
| D-04 | 仮説なし | 生成 | 422 `validation_error` |
| D-05 | 存在しない evidence ID を返すスタブ | 生成 | 502 `ai_invalid_output` |
| D-06 | 有効 + 無効 ID を混在 | 生成 | 無効発言だけ破棄し、有効発言は返す |
| D-07 | 上流 401 | 生成 | 502 `ai_upstream_error`、鍵を漏らさない |
| D-08 | 上流が非 JSON | 生成 | 502 `ai_invalid_output` |
| D-09 | 上流タイムアウト | 生成 | 504 `ai_timeout` |
| D-10 | レート上限 1 | 2 回生成 | 2 回目は 429 |
| D-11 | 生成成功 | 監査を取得 | `ai.debate_requested` があり、鍵・プロンプト・生成本文なし |
| D-17 | 未ログイン | 生成 | 401 `unauthorized` |
| D-18 | 不正スキーマの応答（未知 agent・短すぎる本文・`evidenceIds` が配列でない） | 生成 | 不正な発言だけ破棄し、有効な発言は返す |

### ブラウザ E2E（スタブ）

| ID | 手順 | 期待 |
|---|---|---|
| D-12 | 研究文書を用意 → 03 →「AIで討論を生成」→ プレビュー確認 → 採用 | プレビュー表示、採用前は保存なし、採用後に `debateAi` + `debate[]` が保存される |
| D-19 | プレビュー → 破棄 → 再生成 → 採用 | 破棄でプレビューが消え、保存なし（version・`debateAi` 不変）。再生成後は採用できる |

### 未実行（実キー・人間レビュー）

| ID | 内容 | 理由 |
|---|---|---|
| D-13 | 実在 ID を引くが内容が支持しない発言の検出 | 実キーと人間評定が必要 |
| D-14 | 引用なし事実主張の頻度 | 同上 |
| D-15 | 資料内プロンプトインジェクション | 実キーが必要（P0） |
| D-16 | 根拠不足時の棄権・不確実性表明 | 実キーが必要 |

## 5. 残リスク・未検証

- 実モデルでの幻覚率・品質は未測定。ID 実在チェックは支持関係を保証しない。
- 資料内インジェクションへの耐性は未検証（P0）。
- 本番キー投入は別承認（ADR-0006 と同じ）。
- 費用・レイテンシは既存上限の範囲だが、実測していない。
