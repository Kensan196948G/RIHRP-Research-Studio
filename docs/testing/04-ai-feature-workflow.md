# 04. AI 機能の変更フロー（Skill 適用を必須にする）

- 版: v1.0（2026-11-12）
- 対象: 外部 LLM の呼び出し、プロンプト、AI 生成物を扱う機能の追加・変更
- 関連: [ADR-0006](../adr/0006-ai-drafting.md) / [AI下書きテスト計画](03-ai-drafting-test-plan.md)

## 目的

2026-11-12 の AI 下書き実装では、Skill を実装時に適用せず、記録作成後に事後適用した。
同じ抜けを防ぐため、AI 機能の変更では**フェーズごとに使う Skill を固定**し、
適用状況を検証記録に残す。

## 適用する Skill

| フェーズ | Skill | 目的 |
|---|---|---|
| 設計前 | `ai-feature-testing` | AI 機能のリスク・失敗系・利用者影響の洗い出し |
| テスト設計 | `llm-hallucination-testing` / `test-data-generation` | 幻覚・引用・データ境界の検証設計 |
| 実装後 | `ai-generated-test-review` | AI が書いたテストの過信・弱い assertion の点検 |
| 記録作成 | `test-report-review` | 証跡整合・未検証範囲・残リスクのレビュー |

## 手順

1. 設計前に `ai-feature-testing` をロードし、リスクと失敗系を列挙する。
2. テスト設計で幻覚・引用・データ生成の Skill を必要に応じてロードする。
3. 実装後、AI 生成テストがあれば `ai-generated-test-review` を適用する。
4. 検証記録の作成時に `test-report-review` を適用し、`conditional_pass` 以上の判定と条件を残す。
5. 検証記録に **Skill 名・適用時点（事前/事後/未適用）・理由** を明記する。

## 証跡

検証記録の「実行主体（AI・Agent・Skill）」節に、次を残す。

- 使用したモデルと提供元
- Agent（サブエージェント等）の使用回数
- Skill の適用状況（事前 / 事後 / 未適用と理由）
- 未適用の Skill がある場合、その理由と代替した検証

## 例外

- 該当する Skill が存在しない場合は、その旨と代替手段を記録する。
- 緊急修正で事前適用できない場合は、事後適用とし、その旨を明記する。
