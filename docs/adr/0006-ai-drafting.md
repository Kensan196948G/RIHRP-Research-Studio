# ADR-0006: サーバー側 AI 下書き（生成のみ LLM、検証は決定論のまま）

- 状態: 提案
- 日付: 2026-11-12
- 関連: [ADR-0002](0002-deterministic-verification.md) / [ADR-0003](0003-approval-rule.md)

## 背景

本製品の利用者はブラウザでアクセスする外部ユーザーであり、DSH のモデル認証を利用できない。
現状の API は外部 AI への通信を一切行わず、「AI で下書きする」経路が存在しない。
実 LLM の出力を検証エンジンに通す試験（[2026-11-12](../verification/2026-11-12-real-ai-verification.md)）は
検証側の挙動を確かめたが、**ブラウザ利用者が AI 生成を使う経路**は未検証である。

## 決定

- サーバー側に LLM クライアントを置く。プロバイダは `openai`（OpenAI 互換 /chat/completions）と
  `anthropic`（/messages、`x-api-key` と `anthropic-version`）を切り替えられる。
- 追加する API は **生成のみ**。検証（`verify_claim`）は決定論のまま変更しない（ADR-0002 維持）。
- 生成結果は**保存しない**。候補を返し、利用者が採用したものだけを既存の
  `POST /claims/{id}/evidence` 経路で登録する。
- モデルが返した引用は**サーバー側で原文照合**し、一致しない候補は `valid=false` として返す（採用不可）。
- 秘密は環境変数のみ（`RIHRP_LLM_API_KEY` 等）。キーが無い場合は 503 `ai_not_configured` で
  **機能だけを無効化**し、他の機能は通常どおり動く（fail closed）。
- 上限: 1 回の生成で最大 8 候補、入力は 12,000 文字まで、タイムアウト 30 秒、利用者あたり 5 回/分。
- 監査には生成の事実（source_id, model, 候補数, 有効数, 所要時間）を残し、**プロンプト本文と鍵は残さない**。

## 理由

- 鍵をブラウザへ渡さないため、サーバー側呼び出しが唯一の安全な形。
- 生成物を自動保存しないことで、幻覚・プロンプトインジェクションがそのままデータ化されるのを防ぐ。
- 引用の原文照合をサーバーで行うことで、UI を迂回した登録でも捏造引用は既存の入口ガードで弾かれる。

## 影響

- 新規設定: `RIHRP_LLM_PROVIDER`（openai|anthropic） / `RIHRP_LLM_BASE_URL` / `RIHRP_LLM_MODEL` /
  `RIHRP_LLM_API_KEY`（+ 任意の上限値）。`BASE_URL` が空ならプロバイダ既定を使う。
- キー未設定の環境では UI に「AI 下書きは未設定」と表示し、既存機能は不変。
- 本番のキー投入は人間の判断（別承認）。投入しない限り外部通信は発生しない。

## 代替案

- ブラウザから直接 AI API を呼ぶ: 鍵が配布物に載るため不採用。
- DSH の認証を製品から使う: 外部ブラウザ利用者には存在しないため不採用。
- 生成結果を自動保存: 幻覚がそのまま業務データになるため不採用。
