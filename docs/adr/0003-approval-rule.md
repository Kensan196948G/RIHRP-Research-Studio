# ADR-0003: 承認は「矛盾ゼロ」を必須とし、未検証件数を明示する

- 状態: 提案（2026-11-12 改訂: AI 支援レポートの条件を追加）
- 日付: 2026-11-02

## 背景

レビュー承認が「読んだ」の意味しか持たないと、根拠の無い記述が承認済みとして流通する。一方で、すべてを verified にしないと承認できない設計は、現実の調査（一次情報が取りにくい）で運用が止まる。

## 決定

- レポート承認（`approved`）の条件は **contradicted = 0** とする。
- `unverified` / `insufficient` は承認をブロックしないが、承認 API の応答と UI に件数を必ず表示し、エクスポートにもマーカーを残す。
- 提出者本人は承認できない（職務分離）。
- 差し戻しはコメント 10 文字以上を必須とする。

## 理由

- 矛盾は「根拠と食い違う」= 品質の重大な欠陥であり、止める価値がある。
- 未検証は「根拠が薄い」であり、承認判断は人間に残す。ただし可視化は強制する。
- 承認者と提出者の分離により、自己承認を防ぐ。

## 影響

- 承認 API は 409 `approval_blocked` を返す場合がある。UI は矛盾一覧へのリンクを出す。
- 既存の承認済みレポートの主張を後から編集した場合、版が変わるため再承認が必要（版番号で管理）。

## 代替案

- verified のみ承認可: 一次情報が取れない調査で運用不能になるため不採用。
- すべて人間判断: 矛盾の見落としを防げないため不採用。

## 改訂（2026-11-12）: AI 支援レポートは根拠不足でも承認しない

### 背景

実 LLM に主張と引用を書かせて検証エンジンに通した実地試験（[2026-11-12 実AI検証](../verification/2026-11-12-real-ai-verification.md)）で、
次の挙動を実測した。

- 存在しない引用（捏造）は登録時に 422 で拒否され、**エンジンには到達しない**。
- そのため捏造引用を含む主張は `contradicted` ではなく `insufficient`（根拠 0 件）になる。
- 現行の条件では `insufficient` は承認を止めないので、**捏造引用 4 件を含むレポートが承認できた**。

`contradicted` は「根拠と食い違う」だが、捏造引用は「根拠が無い」として現れる。
AI 生成のレポートでは後者が主要な幻覚であり、これを承認で止めないのは ADR の目的に反する。

### 決定（追加）

- レポート提出時に **AI 支援（LLM 生成の主張を含む）の自己申告** `ai_assisted` を受け取る。
- `ai_assisted = true` のレポートの承認条件は **`contradicted = 0` かつ `insufficient = 0`**（欠落参照も従来どおり不可）とする。
- `unverified` は従来どおりブロックしない（丸め・順序数など、誤りとは限らないため）。
- 申告は提出時に一度立てたら**下げられない**（差し戻し後の再提出でも維持する）。
- 承認 API の 409 応答に `ai_assisted` / `insufficient` と対象主張を含める。

### 影響（追加）

- DB: `reports.ai_assisted`（既定 false）。既存レポートは false のまま。
- UI: 提出前の「AI 支援」チェックと、提出後の注意表示。エクスポートにも AI 支援の有無を残す。
- 自己申告であるため、**虚偽申告は防げない**。AI 生成物を扱う運用では申告を必須にする統制が別途必要。
- `unverified` は引き続き承認を止めないため、数値の丸め・順序数は人間のレビュー対象として残る。
