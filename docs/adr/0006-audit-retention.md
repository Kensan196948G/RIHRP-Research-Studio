# ADR-0006: 監査ログの保持期間と削除（append-only の例外）

- 日付: 2026-11-03
- 状態: 採用（削除ジョブは既定で無効。人間の承認後に有効化する）

## 背景

監査ログ `audit_events` は ADR-0005 に基づき append-only（UPDATE/DELETE 禁止トリガー）で
保護している。一方で、無期限に保持すると容量と個人情報の保持リスクが増えるため、
保持期間を定めて古いレコードを削除する運用が必要になる。append-only の原則と保持期間は
そのままでは両立しないため、例外の条件を明文化する。

## 決定

- 保持期間は **365 日**（`RIHRP_AUDIT_RETENTION_DAYS`、既定 365）。
- 削除は **所有者ロール**で実行する専用ジョブに限定する。アプリのロールはトリガーを
  無効化できないため、通常の API からは削除できない。
- ジョブは **dry-run が既定**。実際の削除は `--commit` と環境変数
  `RIHRP_ALLOW_AUDIT_PURGE=1` の両方が揃った場合だけ行う。
- 削除は 1 トランザクション内で「トリガー無効化 → バッチ削除 → トリガー再有効化」を実行する。
  失敗時はロールバックされ、トリガーは有効なまま残る。
- systemd の `rihrp-audit-purge.timer` は**インストールするが有効化しない**。
  人間が保持方針と実行結果を承認した後に `systemctl --user enable --now` する。
- 実行の記録は systemd journal（`rihrp-audit-purge.service`）に残す。監査テーブル自身への
  削除記録は、削除対象テーブルへの書き込みになるため行わない（この点は既知の制約）。

## 影響

- 365 日を超えた監査イベントは復元できない（バックアップからの復元を除く）。
- 削除中は `audit_events` に ACCESS EXCLUSIVE ロックがかかり、短時間書き込みが待たされる。
- 有効化・保持期間の変更は運用手順（`docs/runbooks/operations.md` §8）に従い、
  実行前にバックアップを取得する。
